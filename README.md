# agentwiki

**A second brain that your AI coding agents write for you.**

agentwiki is an [Obsidian](https://obsidian.md) vault plus a set of [Claude Code](https://claude.com/claude-code) skills and hooks. While agents work in your repos, they keep a wiki of what they did, what broke and how it was fixed, and how each codebase works. The same vault is a study system for courses, books and research.

You read, edit and present from it in Obsidian. The agents do the writing and bookkeeping.

---

## Why

- **"What did I even do on this project last month?"** Every agent session leaves a short, dated work-log entry: the outcome, why it was done, key files and next steps.
- **"I've seen this error before…"** Real bugs and obstacles become issue pages (symptom → cause → fix → lessons). The next session in that repo sees the open issues before it starts debugging.
- **"Can you explain how your project works?"** `/wiki-explain` writes plain-language explainers grounded in the actual code: overview, architecture diagram, module walkthroughs, flows, design decisions, glossary, and a pitch with the questions you'll likely be asked.
- **"I need to actually learn this course."** Lecture and chapter notes, shared concept pages, flashcards, quizzes that track your weak spots, assignment deadlines and exam plans.

## What you get

| Area | Pages | Written by |
|---|---|---|
| `wiki/projects/<repo>/` | hub · work log · ideas · `issues/` · `docs/` (explainers) | agents, automatically (ideas only when you voice them) |
| `wiki/learning/<area>/` | course / book / skill / research hub · `notes/` · `assignments/` | `/wiki-study` |
| `wiki/concepts/` | shared knowledge that links courses ↔ projects | `/wiki-study`, `/wiki-ingest` |
| `wiki/sources/`, `raw/` | cited summaries of articles, papers, slides; immutable originals | `/wiki-capture`, `/wiki-ingest` |
| `wiki/syntheses/` | answers, comparisons and decisions worth keeping | `/wiki-save` |
| `wiki/dashboard.base` | open issues · deadlines · projects · learning · explainers · needs attention | generated by Obsidian Bases |

## How the automation works

After `install-global`, these user-level Claude Code hooks run in **every** repo (and stay silent inside the vault itself):

| Hook | What it does |
|---|---|
| **SessionStart** | Injects the project's open issues, recent work and explainers. In an untracked repo, offers to register it. |
| **Stop** | After a turn with ≥3 file edits, asks the agent to write one work-log entry. Entries are merged per session, so there's no spam. |
| **SessionEnd** | Auto-logs edits that were never summarized, then commits the vault to git. |

Everything is plain Markdown plus git: every change can be reviewed and reverted.

## Requirements

- [Claude Code](https://claude.com/claude-code)
- Python ≥ 3.8 (standard library only)
- git
- [Obsidian](https://obsidian.md) ≥ 1.9 (the Bases core plugin powers the dashboard; the Spaced Repetition community plugin is optional, for flashcards)

## Install

```bash
# 1. Get your own copy. Keep it PRIVATE: it will hold your notes.
#    Use "Use this template" on GitHub, or:
git clone https://github.com/orcrobert/agentwiki.git ~/agentwiki
cd ~/agentwiki

# 2. Check the tooling
python3 _system/wiki.py selftest

# 3. Start the guided setup
claude          # accept the trust prompt for this folder
/wiki-setup
```

Then open the folder in Obsidian ("Open folder as vault").

`/wiki-setup` walks through [`_system/BOOTSTRAP.md`](_system/BOOTSTRAP.md):
1. git
2. selftest
3. installing the user-wide hooks and skills
4. a short interview: which repos to track, what you're studying, deadlines, your courses' AI-use rules
5. Obsidian settings
6. a first real session

> Keep the vault out of iCloud/Dropbox/OneDrive folders: agents write from many repos at once and sync tools create conflict copies.

### Install only the user-wide pieces

```bash
python3 _system/wiki.py install-global --dry-run   # preview
python3 _system/wiki.py install-global             # install
```

This adds to `~/.claude/`:
- the three hooks
- an allow rule for `wiki.py`
- the vault as an additional directory
- a marked block in `CLAUDE.md`
- the skills `wiki-log`, `wiki-idea`, `wiki-explain` and `wiki-recall`

Backups are written as `*.wiki-backup-<timestamp>`. It is safe to re-run.

## Daily use

| You want to… | Do this |
|---|---|
| Just code | Nothing. Work logs and issues get written as you go. |
| Save an idea | Say "idea: …" or run `/wiki-idea …` |
| Understand or present a project | `/wiki-explain` (or `/wiki-explain pitch`, `module <name>`, `refresh`) |
| Remember how something was fixed | `/wiki-recall <error or topic>` |
| Start a course, book or skill | `/wiki-study area <name>` |
| Turn a lecture or chapter into notes | drop slides into `raw/`, then `/wiki-study note <area>` |
| Revise | `/wiki-study quiz <area>` · `/wiki-study cards <area>` · `/wiki-study plan <area>` |
| Track homework or exams | `/wiki-study assignment <area> <title>` |
| Add an article or paper | `/wiki-capture <url> --ingest` (or Obsidian Web Clipper into `raw/`) |
| Ask the wiki | just ask, or `/wiki-query …`; keep good answers with `/wiki-save` |
| See what's going on | `/wiki-status` or open `wiki/dashboard.base` |
| Health check | `/wiki-lint` weekly, `/wiki-lint full` monthly |

More detail: [`_system/README.md`](_system/README.md).

## Principles

- **Signal over noise.** One log entry per session; issues only for things that cost time or could recur; ideas only from you.
- **Grounded.** Explainers cite `path:line` and record the commit they describe (lint flags them when the code moves on). Study pages cite notes and sources.
- **Computed, not maintained.** Indexes, hub listings, open-issue counts, last activity and due dates are generated by `wiki.py`, so they can't drift.
- **Safe by default.** `raw/` is append-only, enforced by a hook. Sources are treated as data, never as instructions. No secrets go into the wiki. Each course's AI-use rules are respected.
- **Portable.** Plain Markdown, YAML frontmatter, wikilinks and git. `AGENTS.md` works for other agents too; the hooks are Claude Code–specific.

## Turning things off

| To stop… | Do this |
|---|---|
| Tracking one repo | `python3 _system/wiki.py project ignore <path>` |
| Work-log reminders | set `WIKI_REMIND=0`, or raise `remind_min_edits` in `_system/wiki.config.json` |
| All the user-wide pieces | `python3 _system/wiki.py install-global --uninstall` |
| The vault autosave | set `WIKI_AUTOSAVE=0` |

## Optional: graphify

[graphify](https://github.com/Graphify-Labs/graphify) turns a folder of code or notes into a knowledge graph. The wiki works fine without it. Off by default; if you have it installed and want the skills to use it:

```bash
python3 _system/wiki.py graphify on    # or: off · no argument shows the status
```

Every graphify step in the skills checks this first and is skipped when it's off or the CLI is missing. Graph output (`graphify-out/`) is scratch: gitignored, never indexed or linted as wiki pages, and never cited as evidence. Claims still cite the code or the pages.

## Repository layout

```
AGENTS.md, CLAUDE.md      operating manual for agents
_system/wiki.py           tooling: project, worklog, issue, idea, new, index, lint, search, context, hook, install-global, selftest
_system/wiki.config.json  page types, fields, enums, thresholds
_system/templates/        page templates
_system/global/           user-wide skills + CLAUDE.md block (installed into ~/.claude)
.claude/                  vault skills, rules and hooks
raw/                      immutable sources
wiki/                     the wiki itself
```

## Development

```bash
python3 _system/wiki.py selftest   # 50 checks in a temporary vault; touches neither your wiki nor ~/.claude
```

Changes to conventions go through `/wiki-schema` and are recorded in [`_system/SCHEMA-CHANGELOG.md`](_system/SCHEMA-CHANGELOG.md).
